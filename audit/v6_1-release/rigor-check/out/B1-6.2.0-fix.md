Rigor: sprint. One contributor, no production data, and the only irreversible action (renaming your real photos) stays out of the agent's reach.

**Mode:** DESIGN. I skipped the full design brief because the ask is narrow. The assumptions it would have recorded are at the end.

## What the environment needs, and what it doesn't

| Layer | Decision | Why |
|---|---|---|
| CLAUDE.md | Yes, about 40 lines | Holds the mission, commands, the rename rules and the stop rule |
| `.claude/settings.json` | Yes, a small allowlist | Lets pytest and read-only git run without prompts. Blocks `git push` |
| Hooks | No | The one real risk is renaming real photos. A design rule handles it better: dry-run is the default and tests only touch `tmp_path`. Pattern-matching paths in a hook would be fragile |
| Skills / subagents / MCP | No | It's one loop on a small codebase, so a subagent wouldn't fix any problem you actually have |
| Reviewer role / gates | No | At sprint rigor, the pytest result is the only check |

## File 1: `CLAUDE.md`

```markdown
# photo-rename

Personal CLI: rename photo files to their EXIF capture date. One contributor.

## Commands
- Test: `python -m pytest -q`
- Run (safe): `python -m photo_rename <dir>`   # dry-run is the default
- Apply: `python -m photo_rename <dir> --apply`

## Rename rules (the contract)
- Name format: `YYYY-MM-DD_HHMMSS<ext>`, extension lowercased.
- Date source, in order: EXIF DateTimeOriginal → DateTimeDigitized → skip file (report it).
  Never fall back to filesystem mtime silently.
- EXIF dates look like `2024:05:01 12:00:00`; colons are illegal in Windows filenames — always reformat.
- Collisions (incl. case-only, Windows is case-insensitive): append `_1`, `_2`, … Never overwrite.
- A file already correctly named is a no-op.
- Dry-run prints `old -> new` for every planned rename and changes nothing.

## Working rules
- Tests build fixture images in `tmp_path` (Pillow can write EXIF). Never commit real photos.
- Never run the CLI with `--apply` on any path outside `tmp_path` or `tests/`.
- Keep the core pure: `plan_renames(paths) -> list[(src, dst)]` is testable without touching disk;
  `apply(plan)` is the only function that renames.

## Routine — no approval needed
Edit code and tests, run pytest, add a dependency to pyproject/requirements, create files under
`src/`, `tests/`, `reports/`, run read-only git commands.

## Stop and ask
- Anything that would rename, move or delete files outside the repo or `tmp_path`.
- `git push`, history rewrites, deleting tracked files.
- A behavior choice the rules above don't settle (e.g. what to do with videos, HEIC, timezone offsets).
Ordinary failures (test fails, import error) are not stop conditions — fix and continue.
```

## File 2: `.claude/settings.json`

```json
{
  "permissions": {
    "allow": [
      "Bash(python -m pytest:*)",
      "Bash(pytest:*)",
      "Bash(git status)",
      "Bash(git diff:*)",
      "Bash(git log:*)"
    ],
    "deny": [
      "Bash(git push:*)"
    ]
  }
}
```

Your machine runs Windows, so Claude Code may run these commands through PowerShell instead of Bash. If you still get prompts for them, run `/fewer-permission-prompts` after the first session. It reads your actual usage and adds the right rules. I haven't checked whether PowerShell commands match these Bash rules, so treat that part as a guess.

```text
Goal: a working, tested first version of the photo-rename CLI per CLAUDE.md.

1. Survey first, report only: list what exists (package layout, existing tests, deps).
   Don't assume any particular starting state; build on whatever is there.
2. Implement `plan_renames` (pure) and `apply` (the only disk-mutating function), plus a
   CLI entry point with dry-run default and `--apply`. Use Pillow for EXIF unless something
   already in the repo dictates otherwise.
3. Tests (pytest, fixtures generated in tmp_path) must cover at minimum:
   - DateTimeOriginal present → correct name
   - only DateTimeDigitized present → used as fallback
   - no EXIF → skipped and reported, file untouched
   - two photos with the same timestamp → `_1` suffix, nothing overwritten
   - case-only collision (`A.JPG` vs `a.jpg` target)
   - already-correct name → no-op
   - dry-run leaves the directory byte-identical
4. Done when `python -m pytest -q` passes with all of the above present.

Routine (no approval): everything listed under "Routine" in CLAUDE.md.
Stop and ask: anything under "Stop and ask" in CLAUDE.md. Do not run --apply on any real folder.

Finish by writing `reports/session_<YYYYMMDD-HHMM>Z.md`, five lines:
what was built / files changed / pytest result line (verbatim) / open questions / next step.
Don't commit the report.
```

## Handoff and when to come back

- **Hand off now.** Put File 1 at the repo root and File 2 in `.claude/`, then paste File 3 into Claude Code. The design work doesn't need anything else first.
- **Before you trust the tool on your real library:** run it yourself in dry-run on a *copy* of one folder and read the `old -> new` list. That check is yours, not the agent's.
- **Come back to the design if:**
  - you add a second contributor or start using the tool on irreplaceable originals without backups (step up to standard rigor and add a merge gate);
  - the same correction comes up in two sessions (add it to CLAUDE.md);
  - you take on HEIC, video or timezone handling (each needs a decision recorded in the Rename rules).

**Assumptions the brief would have recorded:** the repo is under git; Python 3.10 or newer; JPEG first; there's no undo log yet. A JSON undo log written by `apply` is a good second-session feature if you want the tool to be reversible.
