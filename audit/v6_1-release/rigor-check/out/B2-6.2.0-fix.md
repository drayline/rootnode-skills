The design rests on a few decisions:
- **Production access:** no production database passwords on engineers' machines, plus network rules that keep the production database out of their reach. A guard script blocks any command that names production, but it's a backup, not the real protection.
- **Migrations already on `main` can't be changed**, because they may already have run in production. A guard blocks Claude from editing them. Claude can still change files through shell commands the guard doesn't see, so a 3-line CI check is the real enforcement at merge time.
- **Claude never merges, force-pushes, commits to `main`, or deploys.** These are blocked in the settings and by the guard. It can freely branch, commit, push a feature branch and open a draft PR.
- **When Claude must stop and ask (7 cases):**
  - Anything touching production.
  - Editing a migration already on `main`.
  - Destructive SQL (`DROP`, `TRUNCATE`, backfills) or removing old columns and tables.
  - Changes to matching rules, tolerances or rounding.
  - Changes to the expected output of an existing reconciliation test case.
  - Merging or deploying.
  - Work that would need any of the above to finish.

  Failing tests, lint errors and failed local migrations don't stop it; it fixes them and keeps going.
- **One extra agent, a migration reviewer:** read-only, on Sonnet, checking new migrations for table locks, rollback and safety with the version still running. It gets the file paths and checksums but not the author's opinion. After 2 rounds of fixes, a human decides.
- **Gates:**
  - **Merge:** green CI plus approval from one of the other two engineers. For migration PRs, the reviewer's verdict goes in the PR description.
  - **Weekly release:** the rotating release owner runs the week's migrations against a copy of the production schema in staging before deploying.
- **Left out on purpose:**
  - A Postgres MCP server: it would be one more connection that could point at production.
  - Extra planning or coding agents: three engineers on one service don't need them.
  - A hook that runs tests when Claude stops: CI already does that job.
