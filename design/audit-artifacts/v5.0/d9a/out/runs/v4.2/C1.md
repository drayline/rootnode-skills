**Fix the Skill first.** The Skill's own hooks reference (`references/cc-skills-and-hooks-composition.md` §4) gets two things wrong, and a hook built from it would not block anything:

1. It shows a `"matchers": [{"tool_name": ..., "path_pattern": ...}]` schema. Claude Code doesn't read that format. The real format is a `matcher` regex plus a nested `hooks` array. [Anthropic docs: code.claude.com/docs/en/hooks]
2. It says exit code 1 blocks the tool call. It doesn't: exit 1 is a non-blocking error and the write still happens. Only **exit 2** blocks, or exit 0 with JSON that sets `permissionDecision: "deny"`. [Anthropic docs]

The design below follows the Anthropic docs, not the Skill reference. Correcting that reference should be a separate EVOLVE task; I haven't touched it.

## Placement

| Concern | Where it goes | Why |
|---|---|---|
| Never write to `migrations/` | PreToolUse hook | A wrong write can lose production data, so this needs a hard block, not a guideline. [generalizable — §1 decision rule] |
| Telling the agent why it was blocked | The hook's stderr, which Claude sees on exit 2 | The reason shows up at the moment of failure; no CLAUDE.md text is needed for it. |
| Script line endings | `.gitattributes` | A Windows checkout turns the script's line endings into CRLF, and bash then fails with `$'\r': command not found`. |

## File 1: `.claude/settings.json`

If the project already has a `settings.json`, add this `PreToolUse` entry to its existing `hooks` object rather than replacing the file.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit|MultiEdit|NotebookEdit|Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/protect-migrations.sh\"",
            "timeout": 15
          }
        ]
      }
    ]
  }
}
```

The command calls `bash` explicitly, so the script doesn't need an executable bit (Windows checkouts and `core.fileMode=false` both lose it). `$CLAUDE_PROJECT_DIR` keeps the path working whatever the current directory is. [Anthropic docs]

## File 2: `.claude/hooks/protect-migrations.sh`

```bash
#!/usr/bin/env bash
# .claude/hooks/protect-migrations.sh
#
# PreToolUse guard: blocks Claude Code writes to <project root>/migrations/.
#
# Hook contract (Claude Code):
#   stdin   JSON event: tool_name, tool_input, cwd, ...
#   exit 0  allow the tool call
#   exit 2  block it; stderr is returned to Claude as the reason
#   Any other exit code is a NON-blocking error, so every failure path below
#   exits 2 (fail closed) rather than 1.
#
# Platforms: Git Bash on Windows, bash 4+ on Linux. Invoked as `bash <path>`,
# so no executable bit is needed. Needs one JSON parser on PATH: jq,
# python3/python, or node (tried in that order). Without one, any tool call
# whose input mentions the protected directory is blocked.
#
# Human override (set in the shell that launches claude; Claude cannot set it):
#   CLAUDE_ALLOW_MIGRATION_WRITES=1

set -u

PROTECTED_DIR="migrations"   # relative to project root; no leading/trailing slash

PROJECT_ROOT="${CLAUDE_PROJECT_DIR:-$PWD}"
LOG_FILE="$PROJECT_ROOT/.claude/logs/protect-migrations.log"
TOOL_NAME="?"

case "$(uname -s 2>/dev/null)" in
  MINGW*|MSYS*|CYGWIN*) IS_WINDOWS=1 ;;
  *)                    IS_WINDOWS=0 ;;
esac

log() {
  # Best effort: a logging failure never changes the allow/block decision.
  { mkdir -p "${LOG_FILE%/*}" &&
    printf '%s %s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$*" >>"$LOG_FILE"; } 2>/dev/null || true
}

block() {
  log "BLOCK tool=$TOOL_NAME target=$1 reason=$2"
  printf '%s\n' \
    "BLOCKED by .claude/hooks/protect-migrations.sh" \
    "  target: $1" \
    "  reason: $2" \
    "Files under ${PROTECTED_DIR}/ are protected and must not be changed by Claude." \
    "Do not retry or work around this block. Describe the needed migration to the user and stop." >&2
  exit 2
}

INPUT="$(cat)" || block "<stdin>" "could not read hook input"

# Fast path: a write into the protected directory must name it somewhere in
# the event JSON. If the name never appears, there is nothing to check.
shopt -s nocasematch
[[ "$INPUT" == *"$PROTECTED_DIR"* ]] || exit 0
shopt -u nocasematch

if [ "${CLAUDE_ALLOW_MIGRATION_WRITES:-0}" = "1" ]; then
  log "OVERRIDE allow (CLAUDE_ALLOW_MIGRATION_WRITES=1)"
  exit 0
fi

# ---- JSON parsing -----------------------------------------------------------
PARSER=""
if command -v jq >/dev/null 2>&1; then
  PARSER="jq"
else
  for py in python3 python; do
    # The Windows Store "python3" stub is on PATH but fails this probe.
    if command -v "$py" >/dev/null 2>&1 && "$py" -c 'import json' >/dev/null 2>&1; then
      PARSER="$py"; break
    fi
  done
  if [ -z "$PARSER" ] && command -v node >/dev/null 2>&1; then PARSER="node"; fi
fi
[ -n "$PARSER" ] || block "<unparsed>" "no JSON parser (jq, python3/python, node) on PATH; failing closed"

json_get() {  # json_get a.b.c -> string value or empty if absent; non-zero if not JSON
  case "$PARSER" in
    jq)
      printf '%s' "$INPUT" | jq -r --arg k "$1" \
        'getpath($k | split(".")) // empty | if type == "string" then . else tojson end' ;;
    node)
      printf '%s' "$INPUT" | node -e '
        let s = ""; process.stdin.setEncoding("utf8");
        process.stdin.on("data", c => s += c);
        process.stdin.on("end", () => {
          let d = JSON.parse(s);
          for (const k of process.argv[1].split(".")) d = (d && typeof d === "object") ? d[k] : undefined;
          process.stdout.write(d == null ? "" : (typeof d === "string" ? d : JSON.stringify(d)));
        });' "$1" ;;
    *)
      printf '%s' "$INPUT" | "$PARSER" -c '
import json, sys
d = json.loads(sys.stdin.buffer.read().decode("utf-8"))
for k in sys.argv[1].split("."):
    d = d.get(k) if isinstance(d, dict) else None
s = "" if d is None else (d if isinstance(d, str) else json.dumps(d))
sys.stdout.buffer.write(s.encode("utf-8"))' "$1" ;;
  esac
}

TOOL_NAME="$(json_get tool_name)" || block "<unparsed>" "hook input is not valid JSON; failing closed"
[ -n "$TOOL_NAME" ] || block "<unknown>" "hook input has no tool_name; failing closed"
CWD="$(json_get cwd)" || CWD=""

# ---- Path normalization -----------------------------------------------------
canon() {  # separators -> '/', /c/... and /cygdrive/c/... -> c:/..., case-folded on Windows
  local p="${1//\\//}"
  if [[ "$p" =~ ^/cygdrive/([A-Za-z])(/.*)?$ ]] ||
     { [ "$IS_WINDOWS" = 1 ] && [[ "$p" =~ ^/([A-Za-z])(/.*)?$ ]]; }; then
    p="${BASH_REMATCH[1]}:${BASH_REMATCH[2]}"
  fi
  [ "$IS_WINDOWS" = 1 ] && p="${p,,}"
  printf '%s' "$p"
}

normalize() {  # lexical: drop '.', resolve '..', collapse '//'; returns absolute form
  local p="$1" drive="" seg out=() parts=()
  if [[ "$p" =~ ^([A-Za-z]:)(.*)$ ]]; then drive="${BASH_REMATCH[1]}"; p="${BASH_REMATCH[2]}"; fi
  IFS='/' read -r -a parts <<<"$p"
  for seg in "${parts[@]}"; do
    case "$seg" in
      ''|.) ;;
      ..)   [ "${#out[@]}" -gt 0 ] && out=("${out[@]:0:${#out[@]}-1}") ;;
      *)    out+=("$seg") ;;
    esac
  done
  local IFS='/'
  printf '%s/%s' "$drive" "${out[*]}"
}

ROOT="$(normalize "$(canon "$PROJECT_ROOT")")"
GUARD="${ROOT%/}/$(canon "$PROTECTED_DIR")"

is_protected() {
  local p
  [ -n "$1" ] || return 1
  p="$(canon "$1")"
  if [[ "$p" != /* && ! "$p" =~ ^[A-Za-z]:/ ]]; then
    p="$(canon "${CWD:-$PROJECT_ROOT}")/$p"
  fi
  p="$(normalize "$p")"
  [[ "$p" == "$GUARD" || "$p" == "$GUARD"/* ]]
}

# ---- Bash tool: best-effort detection of writes -----------------------------
check_bash() {
  local cmd="${1,,}" seg tgt first i words=()
  local name="${PROTECTED_DIR,,}"
  local ref='(^|[^[:alnum:]_.-])'"$name"'([/\\]|[^[:alnum:]_.-]|$)'
  [[ "$cmd" =~ $ref ]] || return 0

  while IFS= read -r seg; do
    [[ "$seg" =~ $ref ]] || continue

    # 1. Output redirection into the protected directory.
    while IFS= read -r tgt; do
      [[ "$tgt" =~ $ref ]] && block "$1" "shell redirection writes into ${PROTECTED_DIR}/"
    done < <(grep -oE '>>?[[:space:]]*[^[:space:]]+' <<<"$seg")

    # 2. Mutating command whose arguments reference the protected directory.
    read -r -a words <<<"$seg"
    i=0
    while [ "$i" -lt "${#words[@]}" ] &&
          [[ "${words[$i]}" =~ ^[a-z_][a-z0-9_]*= || "${words[$i]}" =~ ^(sudo|env|command|exec|nohup|time|nice|xargs)$ ]]; do
      i=$((i + 1))
    done
    first="${words[$i]:-}"; first="${first##*/}"; first="${first%.exe}"
    case "$first" in
      rm|rmdir|mv|cp|touch|truncate|tee|ln|install|chmod|chown|mkdir|dd|rsync|unlink|shred|patch)
        block "$1" "'$first' modifies paths under ${PROTECTED_DIR}/" ;;
      sed|perl)
        [[ " $seg" =~ [[:space:]](-[a-z]*i|--in-place) ]] && block "$1" "in-place edit under ${PROTECTED_DIR}/" ;;
      git)
        [[ "$seg" =~ [[:space:]](checkout|restore|rm|mv|apply|am|reset|stash|clean|switch|merge|rebase|pull|cherry-pick|revert)([[:space:]]|$) ]] &&
          block "$1" "git operation would modify ${PROTECTED_DIR}/" ;;
      find)
        [[ "$seg" =~ [[:space:]]-(delete|exec|execdir|ok|okdir|fprint)([[:space:]]|$) ]] &&
          block "$1" "find action under ${PROTECTED_DIR}/" ;;
      python|python3|py|node|ruby|pwsh|powershell|bash|sh)
        [[ "$seg" =~ [[:space:]](-c|-e|--eval|-command)([[:space:]]|$) ]] &&
          block "$1" "inline script references ${PROTECTED_DIR}/" ;;
    esac
    [[ "$seg" =~ (set-content|add-content|out-file|new-item|remove-item|move-item|copy-item|rename-item|clear-content) ]] &&
      block "$1" "PowerShell write cmdlet references ${PROTECTED_DIR}/"
  done < <(sed -e 's/&&/\n/g' -e 's/||/\n/g' -e 's/[;|&]/\n/g' <<<"$cmd")
  return 0
}

# ---- Dispatch ---------------------------------------------------------------
case "$TOOL_NAME" in
  Write|Edit|MultiEdit|NotebookEdit)
    key="tool_input.file_path"
    [ "$TOOL_NAME" = "NotebookEdit" ] && key="tool_input.notebook_path"
    TARGET="$(json_get "$key")" || block "<unparsed>" "could not read $key; failing closed"
    [ -n "$TARGET" ] || block "<missing>" "$TOOL_NAME input has no ${key#tool_input.}; failing closed"
    is_protected "$TARGET" && block "$TARGET" "$TOOL_NAME targets ${PROTECTED_DIR}/"
    ;;
  Bash)
    CMD="$(json_get tool_input.command)" || block "<unparsed>" "could not read tool_input.command; failing closed"
    check_bash "$CMD"
    ;;
esac

log "ALLOW tool=$TOOL_NAME (input mentions ${PROTECTED_DIR}; no protected write detected)"
exit 0
```

## Two supporting one-liners (required)

- `.gitattributes`: `*.sh text eol=lf`. Without this line, the hook breaks on Windows checkouts.
- `.gitignore`: `.claude/logs/`

## How it behaves

- **File tools (Write, Edit, MultiEdit, NotebookEdit): hard block.** Before comparing, the script normalizes the path:
  - `\` becomes `/`
  - `/c/...` and `C:\...` are treated the same
  - `..` segments are resolved, so `src/../migrations/x` is caught
  - case is ignored on Windows only
  - relative paths are resolved against `cwd`

  It only matches `migrations/` at the project root. A lookalike such as `migrations_archive/` is allowed.
- **Bash: best effort.** It blocks redirects, mutating commands, in-place edits, mutating git subcommands, `find -delete/-exec`, inline interpreter code, and PowerShell write cmdlets whenever the command mentions a `migrations` path at any depth. Read-only commands like `cat migrations/001.sql` are allowed. `cp migrations/x /tmp/` is blocked; that false positive is deliberate.
- **Fails closed.** If the input is unreadable, there's no JSON parser, or a required field is missing, it exits 2. That only happens when the input mentions `migrations`; everything else takes the fast path and is allowed.
- **Parsers per platform.** Linux CI will normally have `python3`. Windows usually has Python, and an npm-installed Claude Code always brings Node. Git Bash doesn't ship `jq`, which is why the script tries several parsers in order.

## Known gaps (not covered by this hook)

1. **Migration generators.** Tools like `alembic revision`, `prisma migrate dev`, `rails g migration` and `manage.py makemigrations` write into `migrations/` without the path appearing in the command. If the team uses any of these, add matching `permissions.deny` entries, for example `"Bash(alembic revision:*)"`.
2. **Symlinks or NTFS junctions** that point into `migrations/`. The path check is lexical, so it can't see through them.
3. **MCP filesystem tools** (`mcp__*`) don't match this hook's matcher. If you have such a server configured, extend the matcher and its path-field handling.
4. **Unicode-escaped paths in the JSON** would skip the fast path. Claude doesn't emit these in practice.
