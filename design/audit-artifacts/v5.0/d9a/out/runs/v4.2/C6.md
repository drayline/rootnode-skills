## Verdict

**Run the Refuter on the Opus tier at `high` effort.** In frontmatter, use the `opus` alias rather than a pinned model ID. Never run it below the Builder's tier. If a hard spec moves the Builder up to Opus, keep the Refuter on Opus and consider raising it to `xhigh`.

## Why

| Factor | Reasoning | Source |
|---|---|---|
| Reviewer capability ≥ Builder capability | The Refuter is the last check against the real code before a change lands. If it's weaker than the Builder, it just agrees instead of checking, and the loop becomes a rubber stamp that costs an extra run. | [Anthropic docs]-backed mechanism; rule tagged `[generalizable]` in the delegation reference |
| Where to save money | Save on the Scout and the Researcher, not the Refuter. | delegation reference §1 |
| Builder baseline | The Builder runs on Sonnet by default and on Opus for hard specs. Opus is therefore the lowest tier that always meets "Refuter ≥ Builder". | delegation reference §1, Builder tier-switch mechanism |
| Effort | Judgment and verification work gets high effort. The role table sets the Refuter at `high`. | [Anthropic docs] (`effort` frontmatter field) |
| Why not Fable | Fable is for long-running autonomous work and 1M-context work. A Refuter reads one spec and one diff, so Fable's extra capability doesn't pay for its $10/$50 pricing. | delegation reference §1, dated 2026-09-09 |

**Escalation condition:** when a hard spec puts the Builder on Opus, both roles are on the same tier, which is the minimum the rule allows. Raising the Refuter to `xhigh` for those rounds is my own inference, not a rule in the reference `[speculation]`. At `xhigh`, do not set `thinking: disabled`. On Opus 5 that combination returns HTTP 400 [Anthropic docs, v2.1.198+].

## Complete role spec

The skill requires every named role to carry five things: model, effort, tools, isolation, and a return contract with a numeric cap.

```yaml
# .claude/agents/refuter.md (frontmatter)
name: refuter
description: Re-derives a different agent's change against its spec. Returns ACCEPT or REWORK.
model: opus
effort: high
tools: Read, Grep, Glob, Bash
maxTurns: 40          # tuning value, not documented [speculation]
```

| Field | Value |
|---|---|
| Model | Opus tier, via the `opus` alias |
| Effort | `high`; `xhigh` optional when the Builder ran on Opus |
| Tools | Read, Grep, Glob, Bash. No Edit, Write or Agent. |
| Isolation | Spawned fresh, never forked from the Builder, so it doesn't inherit the Builder's reasoning |
| Verifies | Reads the spec and the diff and reruns the test suite itself. Does not accept the Builder's "done" claim as evidence. |
| Returns | `ACCEPT` or `REWORK`, plus must-fix items as file:line and a one-line reason. **Cap: 300 words.** No diff bodies and no full test logs. |

## Three pitfalls

1. **Bash can still write files.** Leaving Edit and Write out of the tool list doesn't make the Refuter read-only, because Bash can modify files. To actually enforce read-only, block it in a PreToolUse hook or with `permissions.deny`, not in the prompt.
2. **A global model setting overrides the Refuter's.** `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` takes priority over the Refuter's `model: opus`. If that variable plus a Sonnet `CLAUDE_CODE_SUBAGENT_MODEL` is set session-wide, the Refuter silently drops below the Builder. `[product fact 2026-09-09 — verify against the running Claude Code version]`
3. **The model names may be out of date.** The reference's model column is dated 2026-09-09 and says "Opus 5". This session reports the Claude 5.5 family (Opus 5.5) as current. The `opus` alias avoids the problem in frontmatter, but the tier table in the reference should be updated, not reworked from scratch.

## Halt triggers for the loop

- After **3 REWORK rounds on the same change**, stop and escalate. This matches the iteration cap in your global CLAUDE.md.
- If the Refuter returns ACCEPT but the tests fail on trunk after merge, revert. That revert belongs in a hook or CI, not in a prompt.
- If the Refuter and Builder disagree about what the spec means, stop and ask you. The spec is the problem there, not the code.
