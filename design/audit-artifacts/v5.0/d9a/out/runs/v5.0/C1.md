**DESIGN mode (narrow ask, so I skipped the design brief).** Below is a hook that fails closed and works on both Windows Git Bash and Linux CI. It blocks Edit, Write, MultiEdit and NotebookEdit calls that target `<project root>/migrations/`, and it blocks shell commands that could write there. I didn't create or edit any files, and none of this has been run yet. The self-test and smoke test at the end are the checks to run.

## Limitations

1. **Bash and PowerShell checking is a best guess.** File-tool writes are blocked reliably. Shell commands are only checked when they name a `migrations` path, use command substitution, or run from inside `migrations/`. A script that writes there without naming the path (for example `python tools/regen.py`, `$MIG_DIR/x`, or a migration generator) gets through. The CI check under "Companion changes" is the backstop that catches every route.
2. **jq is required.** If jq is missing, the hook blocks every write it guards. That's deliberate, because a guard that can't read its input shouldn't allow anything. Git for Windows doesn't ship jq, so every Windows machine needs it installed.
3. **Some facts are product-version-dependent.** Exit-code meanings, the `matcher` format, `$CLAUDE_PROJECT_DIR` and `onFailure` come from the Anthropic hooks docs as recorded in the skill's reference (checked 2026-10-22); confirm them on the version you run. The `PowerShell` tool name and whether `cwd` follows `cd` inside the Bash tool are unconfirmed. The live smoke test below checks the Windows command path from start to finish.

## Design decisions

- **Exit 2, never exit 1.** Any other non-zero exit is a non-blocking error, so the write would go ahead. An EXIT trap turns any crash into exit 2. [Anthropic docs: hooks]
- **`|| exit 2` in the command string.** If the script is missing or unreadable, `bash` exits 127, which on its own would let the write through. The wrapper turns that into a block.
- **`bash "<path>"` instead of running the script directly.** NTFS checkouts lose the executable bit, so the script is passed to bash explicitly. LF line endings are enforced with `.gitattributes`; a CRLF checkout breaks bash.
- **Paths are normalised on both sides before comparing.** Backslashes become `/`, `/c/...` becomes `c:/...`, everything is lowercased (NTFS is case-insensitive), and `.` and `..` are resolved. The check is anchored to the project root, so `src/db/migrations/` is not protected by the file-tool check.
- **The guard protects its own script.** Hook scripts are read on every call, so editing the script would otherwise switch the guard off.
- **Off-switch with an audit trail.** `MIGRATIONS_GUARD_OFF=1` disables the guard and logs a BYPASS row. The agent can't set it, because hooks run in Claude Code's environment, not the Bash tool's.

## File 1: `.claude/settings.json`

If the file already exists, add this object to its existing `hooks.PreToolUse` array instead of replacing the file.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit|NotebookEdit|Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard-migrations.sh\" || exit 2",
            "timeout": 10,
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
```

`onFailure: "block"` makes a timeout block the call instead of letting it through. If your Claude Code version rejects this key, remove it; the 10-second timeout leaves plenty of headroom. Run `/hooks` after installing to confirm the hook is registered.

## File 2: `.claude/hooks/guard-migrations.sh`

```bash
#!/usr/bin/env bash
# guard-migrations.sh -- PreToolUse guard: blocks writes under <project root>/migrations/
# and to this script itself.
# Fail direction: CLOSED. Exit 0 = allow, exit 2 = block (stderr is the reason Claude sees).
# The EXIT trap coerces any other status to 2, so a crash can never become an allow.
# Platforms: Git Bash (Windows) and bash 4+ (Linux CI). Dependency: jq.
# Off-switch: MIGRATIONS_GUARD_OFF=1 (every use is logged). Log override: MIGRATIONS_GUARD_LOG.

trap 'rc=$?
if [ "$rc" -ne 0 ] && [ "$rc" -ne 2 ]; then
  echo "guard-migrations: internal error (rc=$rc); failing closed. Next step: stop and report this hook failure to the operator." >&2
  exit 2
fi' EXIT

GUARD_DIR="migrations"
LOG_FILE="${MIGRATIONS_GUARD_LOG:-${CLAUDE_PROJECT_DIR:-.}/.claude/logs/guard-migrations.log}"
LOG_FILE="${LOG_FILE//\\//}"

log() {  # $1=decision $2=tool $3=detail -- logging never changes the exit status
  local detail="${3//[$'\t\r\n']/ }"
  {
    mkdir -p "$(dirname "$LOG_FILE")" &&
      printf '%s\t%s\t%s\t%s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$1" "$2" "${detail:0:300}" >> "$LOG_FILE"
  } 2>/dev/null || true
}

block() {  # $1=tool $2=detail $3=reason
  log BLOCK "$1" "$2"
  printf 'BLOCKED by .claude/hooks/guard-migrations.sh: %s\n' "$3" >&2
  printf 'migrations/ is write-protected in this repo. Next step: do not retry through another tool, shell, or path. Stop and tell the operator which migration change you need and why.\n' >&2
  exit 2
}

lower() { printf '%s' "$1" | tr '[:upper:]' '[:lower:]'; }

norm() {  # canonical form: lowercase, forward slashes, /c/x -> c:/x, "." and ".." resolved
  local p seg lead=""
  local -a parts out=()
  p="$(lower "$1")"
  p="${p//\\//}"
  case "$p" in /[a-z]/*|/[a-z]) p="${p:1:1}:${p:2}" ;; esac
  case "$p" in /*) lead="/" ;; esac
  IFS='/' read -r -a parts <<< "$p"
  for seg in "${parts[@]}"; do
    case "$seg" in
      ''|.) ;;
      ..) [ "${#out[@]}" -gt 0 ] && out=("${out[@]:0:${#out[@]}-1}") ;;
      *) out+=("$seg") ;;
    esac
  done
  local IFS='/'
  printf '%s%s' "$lead" "${out[*]}"
}

under_guard() {  # $1=raw path; returns 0 if protected
  local raw="$1" abs
  case "$raw" in
    /*|[A-Za-z]:*|\\*) abs="$raw" ;;
    *) abs="$CWD/$raw" ;;
  esac
  abs="$(norm "$abs")"
  [ "$abs" = "$SELF" ] && return 0
  case "$abs/" in "$BASE"*) return 0 ;; esac
  return 1
}

shell_may_write() {  # $1=command $2=1 if cwd is inside migrations/. Returns 0 = treat as a write.
  local c s seg w rest sub
  local re_assign='^[a-z_][a-z0-9_]*=[^[:space:]]*[[:space:]]+(.*)$'
  local re_find='[[:space:]]-(delete|exec|execdir|ok|okdir|fprint|fprint0|fprintf|fls)[[:space:]]'
  local re_sed_inplace='[[:space:]]-[a-z]*i[a-z]*[[:space:]]|[[:space:]]--in-place'
  c="$(lower "$1")"
  c="${c//\\//}"
  if [ "$2" != "1" ]; then
    printf '%s\n' "$c" | grep -Eq '(^|[^a-z0-9_.-])migrations([^a-z0-9_.-]|$)|guard-migrations\.sh' || return 1
  fi
  # Command or process substitution hides what actually runs.
  case "$c" in *'$('*|*'`'*|*'<('*|*'>('*) return 0 ;; esac
  # Output redirection anywhere except /dev/null, $null, or an fd duplicate is a write.
  s="$(printf '%s' "$c" | sed -E 's/[0-9]*>&[0-9-]+//g; s/[0-9&]*>>?[[:space:]]*(\/dev\/null|\$null)//g')"
  case "$s" in *'>'*) return 0 ;; esac
  # Every list/pipeline segment must start with a read-only command.
  while IFS= read -r seg; do
    seg="${seg#"${seg%%[![:space:]]*}"}"
    while [[ $seg =~ $re_assign ]]; do seg="${BASH_REMATCH[1]}"; done
    w="${seg%%[[:space:]]*}"
    rest=" ${seg#"$w"} "
    case "$w" in
      ''|ls|cat|head|tail|less|more|grep|egrep|fgrep|rg|wc|file|stat|diff|cmp|tree|du|sha256sum|md5sum|echo|printf|cd|pwd|true|type) ;;
      get-content|gc|get-childitem|gci|dir|select-string|sls|test-path|get-item|gi|resolve-path|write-output|get-filehash) ;;
      find) [[ $rest =~ $re_find ]] && return 0 ;;
      sed) [[ $rest =~ $re_sed_inplace ]] && return 0 ;;
      git)
        sub="$(printf '%s' "$rest" | awk '{print $1}')"
        case "$sub" in status|diff|log|show|blame|ls-files|grep|rev-parse|cat-file) ;; *) return 0 ;; esac ;;
      *) return 0 ;;
    esac
  done < <(printf '%s\n' "$s" | sed -E 's/\|\||&&|[;|&]/\n/g')
  return 1
}

# ---- main ----------------------------------------------------------------

if [ "${MIGRATIONS_GUARD_OFF:-0}" = "1" ]; then
  log BYPASS "-" "MIGRATIONS_GUARD_OFF=1"
  exit 0
fi

command -v jq >/dev/null 2>&1 ||
  block "-" "jq missing" "jq is not on PATH, so the hook cannot read its input. Operator: install jq (Windows: winget install jqlang.jq, then reopen the terminal and Claude Code; Debian/Ubuntu CI: sudo apt-get install -y jq)."

[ -n "${CLAUDE_PROJECT_DIR:-}" ] ||
  block "-" "no project dir" "CLAUDE_PROJECT_DIR is not set, so the project root is unknown."

INPUT="$(cat)"
field() { printf '%s' "$INPUT" | jq -r "$1 // empty" 2>/dev/null | tr -d '\r'; }

TOOL="$(field '.tool_name')"
[ -n "$TOOL" ] || block "-" "bad input" "hook input is empty, not valid JSON, or has no tool_name."

CWD="$(field '.cwd')"
[ -n "$CWD" ] || CWD="$CLAUDE_PROJECT_DIR"

ROOT="$(norm "$CLAUDE_PROJECT_DIR")"
[ -n "$ROOT" ] || block "-" "bad project dir" "CLAUDE_PROJECT_DIR did not normalize to a usable path."
BASE="${ROOT%/}/$GUARD_DIR/"
SELF="${ROOT%/}/.claude/hooks/guard-migrations.sh"

case "$TOOL" in
  Bash|PowerShell)
    CMD="$(field '.tool_input.command')"
    IN_GUARD=0
    under_guard "$CWD" && IN_GUARD=1
    if shell_may_write "$CMD" "$IN_GUARD"; then
      block "$TOOL" "$CMD" "this $TOOL command could write to a protected path (output redirect, command substitution, or a command outside the read-only allowlist, touching migrations/ or run from inside it)."
    fi
    ;;
  *)
    TARGET="$(field '.tool_input.file_path // .tool_input.notebook_path // .tool_input.path')"
    if [ -z "$TARGET" ]; then
      case "$TOOL" in
        Edit|Write|MultiEdit|NotebookEdit)
          block "$TOOL" "no path" "$TOOL input carries no file path; refusing rather than guessing." ;;
      esac
    elif under_guard "$TARGET"; then
      block "$TOOL" "$TARGET" "$TOOL targets a protected path ($TARGET)."
    fi
    ;;
esac

exit 0
```

```markdown
## Protected paths
- `migrations/` is write-protected by a PreToolUse hook (`.claude/hooks/guard-migrations.sh`). Read freely; never write.
- Halt and escalate when: (1) the guard blocks a call, (2) the guard reports an internal error or missing jq,
  (3) the task cannot be completed without a migration change. Report the exact change needed and why.
- Out of scope: retrying via another tool, shell, or path; editing the guard script or the hooks block in settings.json.
```

## Remaining gaps

- Writes made indirectly through scripts, variables or generators aren't detected; the CI check catches them.
- Symlinks into `migrations/` aren't resolved.
- `.claude/settings.json` itself isn't guarded. The hooks setting is loaded at session start, so an edit doesn't take effect mid-session, but it would on the next run. Your global CLAUDE.md already puts settings edits out of scope.
- Shell checks will sometimes block harmless commands, for example `sed --in-place` on another directory in the same command, or anything writing to a nested `*/migrations/`. Those blocks are the safe direction; tell me if they cause friction.
