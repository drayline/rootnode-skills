## 2. Delegation briefs

### Digest helper

The loop relies on content digests. This is a proposed `scripts/digest.mjs`, which the user creates (I created no files):

```js
// LF-normalized sha256 of a file arg, or of stdin when no arg is given.
import { createHash } from 'node:crypto';
import { readFileSync } from 'node:fs';
const raw = process.argv[2] ? readFileSync(process.argv[2], 'utf8') : readFileSync(0, 'utf8');
process.stdout.write(createHash('sha256').update(raw.replace(/\r\n/g, '\n')).digest('hex') + '\n');
```

- Spec digest: `node scripts/digest.mjs specs/{SPEC}.md`
- Diff digest: `git diff main...{BRANCH} | node scripts/digest.mjs`

### Builder brief (ten fields)

```

1 GOAL: Implement specs/{SPEC}.md exactly as written. Nothing beyond its acceptance criteria.
2 IN SCOPE: specs/{SPEC}.md; packages named in the spec's "Affected packages" section; their tests.
3 MAY CHANGE: source and test files inside those packages. Adding a dependency is allowed but must be

  Report each exit code. Do not re-review your own diff; the Refuter does that.
5 DO NOT: edit specs/**, CLAUDE.md, .claude/**, CI config, other packages' public APIs or schemas;
  delete or skip tests; use --force; commit to main; spawn subagents.
6 RETURN FORMAT:

  STATUS: done | status: blocked (reason)

  TESTS: command -> exit code, pass/fail counts
  DEVIATIONS: each departure from the spec, with the clause it departs from (or "none")
  OPEN QUESTIONS: (or "none")
7 RETURN CAP: 40 lines. Write the return before turn {MAX_TURNS - 3}.
8 ALREADY KNOWN: {repo facts the orchestrator already has: package layout, test runner, prior REWORK must-fixes}
9 (header above)
10 n/a (Builder)
```

On REWORK, send the must-fixes to the same Builder by agent ID, with its context intact, using the same return format. `[Anthropic docs — resume by ID / SendMessage]`

### Refuter brief (ten fields)

```
SPEC_DIGEST: {SPEC_SHA256}  DIFF_DIGEST: {DIFF_SHA256}   # recompute both first; halt on mismatch
1 GOAL: Decide whether branch {BRANCH} satisfies specs/{SPEC}.md. Try to disprove each claim first,
  then re-derive the survivors from spec + diff.
2 IN SCOPE: specs/{SPEC}.md; `git diff main...{BRANCH}`; files the diff touches and their direct callers;
  worktree at {WORKTREE_PATH}.
3 MAY CHANGE: nothing. Read-only review.
4 VERIFY (external artifacts): run `pnpm test` (and the per-package filters) yourself in {WORKTREE_PATH};
  check each acceptance criterion against code or a test that covers it. A "done" claim is not evidence.
5 DO NOT: fix code, suggest refactors outside the spec, review unchanged packages, read the Builder's
  report or reasoning (not provided, by design).
6 RETURN FORMAT:
  ROLE: refuter | SPEC: {sha} | DIFF: {sha} | HEAD: {sha}
  Verdict Dictated: yes|no
  VERDICT: ACCEPT | REWORK | status: blocked (reason)
  MUST-FIX (REWORK only): [severity] path:line — spec clause broken — what fails
    top severity also needs: one-step repro + concrete loss, or re-rate it
  CRITERIA: each acceptance criterion -> covered-by (path:line or test name) | NOT COVERED
7 RETURN CAP: 60 lines. Write the verdict before turn {MAX_TURNS - 3}.
8 ALREADY KNOWN: package layout; test command; prior-round must-fixes (round 2 only).
9 (header above)
10 This brief names no preferred verdict and carries none of the Builder's plan.
```

## 3. Loop rules

1. **One spec per loop.** The orchestrator takes one `specs/*.md`, records its digest, commits any pending orchestrator edits (never auto-commit), then sends the Builder out. A worktree branches from the default branch, not from `HEAD`, so uncommitted work would be invisible to the Builder. `[Anthropic docs — sub-agents]`
2. **Check the identity line first.** Before reading the body of any return, the orchestrator checks its first line against the expected role, digest, and HEAD. A mismatch means the return is discarded and re-sent once.
3. **The Refuter is always fresh and non-fork.** Each round gets a new Refuter instance that never inherits the Builder's conversation.
4. **The cycle cap is 2.** Builder→Refuter→REWORK→Builder→Refuter is the maximum. After round 2, the work goes to the operator gate (Aaron) with the open must-fixes listed. At the gate, after 3 REWORK verdicts in total, also offer "accept as-is with open findings". This is stricter than the 3-cycle floor in your global rules, which they allow.
5. **Incomplete returns.** A Refuter return with no verdict is re-sent once. A second one is recorded as `NOT-READY` and goes to the operator gate. A failed Builder is retried once with less context, then the orchestrator either runs it inline or skips it and records why. Never a third identical retry.
6. **`blocked` is not empty.** A `status: blocked` return never counts as ACCEPT or as "no findings".
7. **The receipt freezes.** An ACCEPT is tied to the diff digest it reviewed. Any later write to a reviewed file voids it, and the loop restarts at a fresh Refuter, not at "done".
8. **ACCEPT goes to a merge gate.** Merging needs the operator's approval. Running `pnpm test` on trunk after the merge, and reverting on red, belongs in CI, not in a prompt.
9. **Spec changes stop the loop.** If a spec's digest changes mid-loop, the loop halts. The Builder never edits `specs/**`.
10. **Write a session report when the loop ends.** It goes in `reports/{CODE}_loop_{SPEC}_{YYYYMMDD-HHMM}Z.md` and records computed state: spec and diff digests, branch HEAD, `git diff --name-status` rows, test exit codes per round, verdict per round, open must-fixes, and what the report does not prove. It is committed in the next commit cycle, not by this loop.
11. **Ultracode stays off.** It is never turned on for the whole session. This loop is routine editing.

A hook only blocks on exit code `2` (or exit `0` with `{"decision":"block"}`). Any other non-zero code is reported as an error and the edit still goes ahead. `[Anthropic docs — hooks, fetched 2026-10-22]`

## 5. What the loop may do on its own, and when it stops

| Tier | Items |
|---|---|
| **Autonomous** | Builder edits and adds tests inside the affected packages; Refuter reads and runs tests; orchestrator computes digests and writes the session report |
| **Do, then tell Aaron** | New dependency (lockfile change); a diff touching 3+ packages; any DEVIATIONS entry |
| **Stop and ask** | Edits to `specs/**`, CLAUDE.md, `.claude/**`, or CI; public API or schema changes not named in the spec; deleting or skipping tests; `--force`; anything on main; history rewrites |

**Halt triggers.** Each one produces a halt note naming the trigger that fired:
1. Spec or diff digest mismatch.
2. Cycle cap reached (rule 4) or `NOT-READY` (rule 5).
3. `pnpm test` fails before any change is made.
4. The Builder reports an ambiguous root cause, or an OPEN QUESTION that the spec doesn't answer.
5. A regression appears in a package outside the spec's scope.
6. Any item in the "Stop and ask" tier.
7. The receipt-freeze hook fires after an ACCEPT.

**Handoff and when to come back to design.** The loop is ready to hand to Claude Code once the agent files, `scripts/digest.mjs`, and the two hooks exist and one trial spec has gone through end to end. Return to design work if:
- REWORK keeps tripping on the same must-fix across 2+ specs (add a rule, or a Debugger role);
- specs keep needing code found across many packages (add a Haiku Scout);
- the cycle cap is hit on most specs (the specs are too coarse; split them).
