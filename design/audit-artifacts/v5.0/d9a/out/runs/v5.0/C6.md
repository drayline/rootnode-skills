## RESEARCH MODE: Refuter model and effort in the Builder-to-Refuter loop

**Verdict:** Run the Refuter on **Opus 5.5 at `high` effort**. Only move it up (to `xhigh`, or to Fable 5.1) when your own evals show a measured gain. Don't move it down.

### Gap

The Refuter is the last check against real artifacts before a change lands. It re-derives a *different* agent's diff against the spec and reruns the tests itself. If the reviewer is weaker than the builder, the loop produces agreement instead of verification: it becomes a rubber stamp, and you still pay for the extra call. `[Anthropic docs — sub-agents]` + `[rootnode-cc-design cc-delegation-patterns §1, §4]` `[generalizable — the reasoning doesn't depend on the domain]`

### Candidates

| Candidate | Source class | Fit |
|---|---|---|
| **Opus 5.5 @ `high`** | Tier 1 model guidance + skill role table | Matches the reference role table exactly. Meets the reviewer ≥ builder rule for both Builder tiers (Sonnet 5.5 baseline, Opus 5.5 for hard specs). |
| Opus 5.5 @ `medium` | Tier 1: Anthropic says Opus 5.5 at `medium` "matches or exceeds Opus 5 at `high` on coding and knowledge-work evaluations" | A reasonable default for the orchestrator, but verification is exactly the case where the guidance says to step up to `high`. |
| Opus 5.5 @ `xhigh` | Tier 1 effort guidance | Only on measured gain. It adds cost and latency, and there's no evidence it catches more for ordinary diffs. |
| Fable 5.1 | Tier 1 tier guidance | Kept for long-horizon runs where Opus 5.5 at higher effort still fails your evals. Very few single-diff refutes are long-horizon. |
| Sonnet 5.5 @ `high` | Tier 1 (cost-optimal for lighter agentic work) | **Reject.** It breaks reviewer ≥ builder whenever the Builder is promoted to Opus. At `xhigh`/`max` it also launches reviewer subagents on its own, which is a delegation-cap problem inside a review role. `[Anthropic docs]` |

### Fit analysis

- **Builder on Sonnet 5.5 (baseline):** an Opus 5.5 Refuter is a strictly stronger reviewer. This is the intended asymmetry: save money on Scout and Researcher, not on the Refuter.
- **Builder on Opus 5.5 (hard spec):** an Opus 5.5 Refuter at `high` equals the Builder's tier and effort, so the rule still holds. The independence comes from a fresh, non-fork context and a brief that doesn't dictate the verdict, not from a higher tier. `[cc-delegation-patterns §2 field 10, §4]`
- **Thinking:** it can't be disabled on Opus 5.5. Effort is the only control, so `high` is a real setting, not decoration. `[Anthropic docs]`
- **Failure mode to watch:** a Refuter that returns ACCEPT on diffs a later CI run fails. That's the signal to test `xhigh`. Don't pre-emptively raise effort without it.
- **Tool reach:** Read, Grep, Glob and Bash. Bash is there so the Refuter can rerun the suite, and it is the one tool that can write. Leave out Edit and Write so it can't quietly fix what it's judging. If you need a hard read-only guarantee, add a PreToolUse hook (`exit 2`) that restricts Bash to the test command. `[cc-delegation-patterns §5]` + `[Anthropic docs — hooks]`

### Recommendation

**Adopt Opus 5.5 at `high`** and set it through the mechanism, not in prose. Paste-ready agent frontmatter:

```yaml
---
name: refuter
description: Re-derives a different agent's diff against the spec; returns ACCEPT, REWORK with must-fixes, or status: blocked.
model: opus        # [product fact 2026-10-22 — verify against the running Claude Code version]
effort: high       # [product fact 2026-10-22 — verify against the running Claude Code version]
tools: Read, Grep, Glob, Bash
maxTurns: 30       # [product fact 2026-10-22 — verify against the running Claude Code version]
---
```

Fork mode is on by default. Spawn the Refuter non-fork, or set this in the session environment:

```text
CLAUDE_CODE_FORK_SUBAGENT=0   # [product fact 2026-10-22 — verify against the running Claude Code version]
```

`maxTurns: 30` is a placeholder. Size it to your diffs, and keep the last turns free so the return gets written before the cap.

**Escalation rule:** stay on `high`. Move to `xhigh` only after an A/B run on your own recent diffs shows real findings that `high` missed. Move to Fable 5.1 only if `xhigh` still fails those evals. Lowering the Refuter's tier to save money is out of bounds.
